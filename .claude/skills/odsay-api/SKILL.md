# ODsay 연동

공식 문서: https://lab.odsay.com/guide/releaseReference

## 시작 전 반드시 확인
- API 키 타입이 **Server(IP)** 인지. Android 타입 키는 웹앱에서 동작하지 않는다.
- 등록된 URI/IP 안에서 호출하는지 (각 5개까지 등록 가능).
- 키는 서버 전용. `ODSAY_API_KEY`를 클라이언트 번들에 넣지 않는다.

## 연동 절차
1. **실제 응답을 먼저 본다.** 문서 예시를 믿지 말고 개발용 프록시나 ODsay MCP로 한 번 호출해 실제 JSON을 확보한다.
2. 그 응답을 `tests/fixtures/odsay/<endpoint>.json` 으로 저장한다. 이후 모든 테스트는 이 픽스처를 쓴다.
3. 필드 의미와 함정을 `docs/api-notes.md` 에 한 줄씩 기록한다 (단위, null이 오는 조건, 좌표계 등).
4. `lib/odsay/client.ts` 에 호출 함수를, `lib/odsay/normalize.ts` 에 내부 타입 변환을 쓴다. **외부 응답 형태를 lib 밖으로 내보내지 않는다.**
5. 캐시를 붙인다. 키는 `odsay:<endpoint>:<정규화된 파라미터>`.

## 캐시 정책
| 데이터 | TTL | 이유 |
|---|---|---|
| 경로 검색 결과 | 10분 | 호출 한도가 문서에 없어 히트율이 최우선 |
| 정류장·노선 메타 | 24시간 | 거의 안 변함 |
| 좌표→정류장 검색 | 24시간 | 위와 동일 |

파라미터는 캐시 키를 만들기 전에 정규화한다(좌표 소수점 5자리 반올림, 정렬된 키 순서).

## 반드시 기억할 제약
- **ODsay는 멀티모달 조합 경로를 만들어주지 않는다.** 지하철·버스·도보 구간을 이어붙이는 조합은 `lib/routing/` 에서 직접 한다.
- 지도 타일을 주지 않는다. 노선 그래픽(좌표열)만 준다 → 지도는 카카오맵 JS SDK에 그린다.
- 접근성 정보, 실시간 도착, 요금 결제는 제공하지 않는다.
- 호출 한도가 문서화되어 있지 않다. 429/한도 초과 응답을 정상 경로로 처리하고, 캐시된 값이 있으면 그걸로 폴백한다.
- 공공데이터포털과 정류장 ID 체계가 다르다. 교차 참조는 `stop_id_map` 테이블을 거친다.

## 에러 처리
- 타임아웃 5초, 재시도 1회(지수 백오프).
- ODsay는 HTTP 200에 에러 바디를 담아 보내는 경우가 있다. **상태코드만 보고 성공으로 판단하지 않는다.** 바디의 error 필드를 먼저 확인한다.
- 사용자에게는 일반화된 메시지를 보여주고, 원인은 서버 로그에만 남긴다.
