# 모바일 웹 UI 규칙

1차는 폰 브라우저용 모바일 웹이고, 이후 Capacitor로 감싸 스토어에 올린다. 그래서 **처음부터** 아래를 지킨다.

## 하이브리드 대비 (App Store 심사 4.2 최소 기능 대비)
- safe-area: 상·하단에 `env(safe-area-inset-*)`를 반영한다. 하단 고정 요소는 반드시 `padding-bottom: env(safe-area-inset-bottom)`.
- 터치 타깃 최소 44×44px. 링크·아이콘 버튼 포함.
- 하단 고정 탭바를 레이아웃에 둔다.
- 커스텀 오프라인 화면을 둔다. 브라우저 기본 오류 화면이 보이면 안 된다.

## 레이아웃
- 기준 폭 375px. 모든 화면이 320px에서도 가로 스크롤 없이 동작해야 한다.
- 시안은 Google Stitch 기준. 임의로 디자인을 바꾸지 않는다. 시안에 없는 상태(로딩·빈 상태·에러)는 기존 토큰으로 만들되 사용자에게 확인받는다.

## Tailwind v4
- 색·간격·폰트는 `app/globals.css`의 `@theme` 토큰으로만. 임의 값(`text-[#1a2b3c]`) 금지.
- 반복되는 조합은 컴포넌트로 뽑는다. `@apply` 남용 금지.

## 접근성
- 모든 인터랙티브 요소에 접근 가능한 이름. 아이콘 버튼에는 `aria-label`.
- 폼 입력에 `<label>` 연결. 에러 메시지는 `aria-describedby`로 연결.
- 색만으로 정보를 전달하지 않는다.
- 교통약자 역할이 1차 범위 밖이어도 위 기본은 지킨다.

## 상태 표현
모든 데이터 화면은 4가지 상태를 반드시 갖는다: 로딩(스켈레톤) / 정상 / 빈 결과 / 에러(재시도 버튼).
