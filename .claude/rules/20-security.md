# 보안 규칙 (타협 불가)

## 비밀값
- 키·비밀번호·토큰을 코드나 커밋에 절대 넣지 않는다. `.env.local`만 사용하고 `.env*`는 gitignore.
- 클라이언트 번들에 들어가도 되는 값만 `NEXT_PUBLIC_` 접두어를 쓴다. 카카오 **JavaScript 키**만 해당. REST 키·ODsay 키는 서버 전용.
- 외부 API는 전부 `app/api/**/route.ts` 프록시를 거친다.

## 인증
- 비밀번호 해시는 argon2id (또는 bcrypt cost≥12). 평문·SHA 단독 금지.
- **로그인 5회 실패 시 계정 잠금.** 시간 경과로 자동 해제되지 않으며, 비밀번호 재설정으로만 풀린다.
- 회원가입에 이메일 필수. 비밀번호 재설정 링크를 이메일로 보낸다.
- 재설정 토큰: 랜덤 32바이트, **SHA-256 해시만 DB에 저장**, 유효 30분, 1회용.
- 계정 열거 방지: 이메일 등록 여부와 무관하게 항상 같은 결과 화면을 보여준다.
- 세션 로직은 `lib/session.ts` 한 곳에만. 하이브리드(Capacitor) 전환 시 웹뷰에서 SameSite=Lax 쿠키가 막힐 수 있으므로 토큰 방식으로 바꾼다 — 그때 이 파일만 고치면 되도록 유지한다.

## DB / RLS
- **`POSTGRES_USER=app`은 슈퍼유저이고 슈퍼유저는 RLS를 통째로 우회한다.**
- 애플리케이션 런타임은 전용 역할 `moveone_app`을 쓴다. `DATABASE_URL`은 반드시 `moveone_app`.
- 마이그레이션만 `app`으로 실행한다.
- 사용자 데이터가 들어가는 모든 테이블에 RLS 정책을 켠다. 새 테이블을 만들면 같은 SQL 파일(`db/NNN_*.sql`)에서 `ENABLE ROW LEVEL SECURITY`와 정책, `GRANT ... TO moveone_app` 까지 함께 쓴다. 정책 없는 RLS는 전면 차단이다.
- 쿼리는 `lib/db.ts` 의 `query()` 로, `$1,$2` 바인딩만. 문자열 연결 금지.
- 로그인·가입·재설정은 사용자를 알기 전에 일어나므로 `SECURITY DEFINER` 함수로 좁게 열려 있다. 이 통로를 넓히지 않는다.
- 존재하지 않는 아이디의 로그인 시도도 `login_attempts` 에 기록한다. 기록하지 않으면 응답 차이로 계정 존재 여부가 새어나간다.

## 메일
- `lib/mailer.ts` 어댑터를 통해서만 보낸다.
- 개발: `MAIL_TRANSPORT=console` (터미널 출력). 실발송은 `sendViaSmtp` 구현 후 전환.

## 로그
- 로그에 비밀번호·토큰·세션 ID·이메일 전문을 남기지 않는다.
