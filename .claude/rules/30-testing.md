# 테스트와 검증

## 검증 게이트
`pnpm verify` = `typecheck` → `lint` → `test` → `build`. 커밋 전 반드시 통과.
E2E(`pnpm test:e2e`)는 화면을 건드린 티켓에서만 돌린다.

`pnpm test` 는 **ODsay를 호출하지 않는다.** `fixtures/odsay/*.json` 을 읽는다.
API 키가 없어도 통과해야 정상이다. 통과하지 않으면 테스트가 잘못된 것이다.

## 반드시 테스트하는 것
- `lib/odsay/normalize.ts` — 정규화. 실제 응답 샘플 기준. 필드 누락·빈 배열 포함.
- `lib/routes.ts` — `sortRoutes()` 4종 정렬, 포매터, 요약 칩(3분 이하 도보 생략).
- `lib/region.ts` — 수도권 판정 경계.
- `lib/cache.ts` — 키 정규화, TTL 만료.
- 인증 — 실패 5회 잠금, 재설정 토큰 만료·재사용 거부, 계정 열거 방지.
- 조합 엔진(`lib/routing/`, 생기면) — 환승 0회, 도보만, 후보 없음, 동일 출도착.

테스트하지 않는다: UI 스타일, Next.js 프레임워크 동작, 외부 API 자체.

## 규칙
- 구현이 아니라 **동작**을 검증한다. 내부 함수 호출 여부를 단언하지 않는다.
- 실제 응답을 받으면 `fixtures/odsay/` 를 교체한다. 구조가 달라졌으면 테스트가 실패해 알려준다.
- 시계·랜덤은 고정한다 (`vi.useFakeTimers()`).
- 테스트 이름은 한국어로 "…면 …해야 한다".
- 버그 수정은 **먼저 실패하는 테스트**를 쓰고 고친다.
- 커버리지 숫자를 목표로 삼지 않는다. 위 목록이 커버되면 된다.

## E2E (Playwright)
- 핵심 흐름 2개만 유지: ①가입→로그인→로그아웃 ②출발/도착 입력→경로 목록→상세.
- 외부 API는 `page.route()` 로 `fixtures/` 응답을 물린다.
- 셀렉터는 `getByRole` / `data-testid`. CSS 클래스 셀렉터 금지.
- 모바일 뷰포트(Pixel 7) 기준. 데스크톱은 보지 않는다.
